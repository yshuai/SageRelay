Git + Markdown 静态文档站，不用托管知识库平台与数据库 ​

"知识库"有三种做法：Git + Markdown 静态文档站、托管知识库平台（语雀/飞书/Notion）、自建动态站 + 数据库。决定采用静态文档站：每个词条为带结构化 front-matter（领域/来源级别/发文字号/发布日期/版本状态/标签）的 Markdown 文件，筛选与全文检索在构建期或前端完成，不需要后端。

理由：① 用户是搜"高血压 饮食指南 卫健委"这类词来的，SEO 是获客命脉，平台站的搜索权重和自定义能力差；② 平台对健康内容的审核政策与关停风险不受控，所有权必须在自己手里；③ 版本归档（旧版指南"已被 XX 年版替代"的展示）在 Git 里是天然能力；④ 纯文字内容让 Git 的可对比、可校对特性发挥到极致；⑤ 结构化 Markdown 语料库本身是未来 B 端授权与 AI 层的直接资产。

Considered Options ​

  • 托管知识库平台：上线最快，但丢失 SEO、所有权、版本归档，被否决。
  • 动态站 + 数据库：只有当筛选维度复杂到前端做不动时才需要；词条量到那个规模前属于过度设计，被否决。
